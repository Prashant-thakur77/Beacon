# Beacon Night Shift — AssemblyAI Voice Agent deck (10 slides)

*Source for the `.pptx` / PDF. One idea per slide; the speaker line is what is said, not what is written. Every number below was measured on 21 Sep against the live socket and the live AWS account; screenshots live in `docs/assets/`.*

| # | Title | On the slide | Speaker line (≤ 20 s) |
|---|---|---|---|
| 1 | **The on-call agent you can interrupt** | Cover: Night Board mid-approval. One line: *"A voice agent whose most important sentence is a tool call that can change production."* | Every voice-agent demo is a receptionist. This one holds write access to AWS, and the transcript is the safety artifact. |
| 2 | **03:12, phone in hand** | The night as a row: page on Telegram → *"isko fix kar do"* (voice note) → read-back → *"approve fix one"* → verified → *"grant contract for seven days"* → *"open the pull request"* → 07:00 morning report. | Four questions at 3 AM: is it real, what changed, what do I do, can I go back to sleep. The fifth, nobody asks: will it happen again. That one ends with a pull request. |
| 3 | **Where AssemblyAI sits** | Diagram: browser ⇄ `wss://agents.assemblyai.com/v1/ws` (Universal-3 Pro, turn detection, managed LLM, TTS, nine client-side tools) ⇄ `POST /tools/<name>` on the voice Lambda ⇄ the unchanged backend (registry, Step Functions, DynamoDB). Telegram voice notes ⇄ pre-recorded STT. Audit ⇄ session recordings. | The Voice Agent API is the mouth and the ears; every tool runs on our side with the raw transcript in hand. Pre-recorded STT where a voice note is a file. Recordings where the audit needs proof. |
| 4 | **Consent from the transcript** | Code strip: `approve_fix(fix_id, confirmation_phrase)` ignores its model-written argument and checks `ctx.transcript`. Telegram: `words[].confidence` → min-word gate 85 % → *"I heard 'approve fix one' at 71 % — send it once more."* Screenshot: the audit row with *AssemblyAI live · ▶ Listen*. | The model can call the tool. Only what the engineer actually said — and, on voice notes, how clearly — can make it succeed. And you can play the recording behind every approval. |
| 5 | **Barge-in with a safety meaning** | Screenshot: the read-back cut mid-sentence, *interrupted* pill, console note *"Fix 1 withdrawn — you spoke over the read-back"*; then *"approve fix 1"* refused: *"fix 1 was withdrawn because you interrupted the read-back; nothing was applied."* | Interrupting Beacon during a read-back does not just stop the audio, it withdraws the fix. Turn-taking as a control. |
| 6 | **Hinglish, because 3 AM IST is someone's peak** | Transcript strip: `क्या हुआ है?` → brief in Hinglish (*"U S east 1 mein web service R D S se connect nahi kar paa rahi hai"*); `इसको फिक्स कर दो।` → `propose_fix` in 12 s of speech; *"Approve fix five."* accepted by the phrase check. | Universal-3 Pro takes the code-switching; the agent answers in Hinglish; the exact phrase is still required. Tested by pushing Polly Hindi through `input.audio`, not by hoping. |
| 7 | **Drop-safety and resume** | Sequence from the harness log: `approve fix 3` spoken → socket aborted → `resume` refused → fresh session; incident still `awaiting_engineer`, zero approvals. | If the call drops, the worst case is that nothing happens.
