## 1. The Idea

**Name:** Beacon (keep). Subtitle in every artifact: **Beacon Night Shift**. Renaming would burn hours on stack names, SSM paths, Lambda names, docs and CloudFormation prefixes for zero judge value.

**Tagline:** *The on-call agent that fixes the 3 AM page with your voice, and the second time it happens, does not wake you at all.*

**The audacious hook:** Beacon turns the 3 AM page into a 90-second conversation in the browser that ends with the alarm back to OK, and then lets the engineer say "handle this yourself for a week." That sentence becomes a **Sleep Contract**: a scoped (alarm + action + exact resource ids), expiring, max-uses standing approval that carries the engineer's own transcript as evidence. The next time the same alarm fires with the same fingerprint on the same resources, Beacon runs the same allowlisted fix through a Step Functions loop that dry-runs, executes, verifies recovery on CloudWatch (alarm OK after the execute, the metric at zero, and the action's own post-condition), and only pages a human if verification fails. Every approval, whether spoken tonight or granted for the week, is executed exactly once, under a write-only IAM role scoped by resource tag, and ends with proof.

**30-second pitch:** "It is 3 AM. Payments are failing. You are alone, half-asleep, phone in hand. You need four answers: is it real, what changed, what do I do, can I go back to sleep. Beacon reads the logs on Bedrock, finds the CloudTrail change that caused it, proposes one allowlisted fix, and waits for your word. You say 'approve fix one'. A Step Functions loop applies it and watches the alarm until it clears. Then Beacon asks: handle this myself next time? You say yes, for a week. Next time it fixes it while you sleep and emails you in the morning. Zero humans woken."

**Who it is for:** solo and small-team on-call engineers, especially Indian startups on-call for US/EU traffic (3 AM IST is their customers' peak), indie SaaS, agencies running client AWS accounts, and anyone below the PagerDuty-plus-SRE-team budget line. The person who currently spends 15-40 minutes with a laptop to answer "what changed?" and whose most common page is a repeat of something already fixed once.

**Why now:** (1) Nova 2 Lite makes an RCA plus a tool-calling agent cheap enough to run on every alarm (cents per incident). (2) Strands Agents SDK, Powertools, Step Functions and tag-conditioned IAM make a *safe* remediation loop a weekend build instead of a quarter. (3) Browser speech (Transcribe streaming + Polly) removes telephony from the critical path; voice at 3 AM no longer means a phone system. (4) Managed voice-agent stacks (AssemblyAI Voice Agent API with JSON-Schema tool calling) mean the same six tools can later carry barge-in, turn-taking and Hinglish without touching the backend.

### 4.3 Data flow (one incident, by the numbers)

1. `make break-demo` revokes tcp/5432 from the RDS SG (CloudTrail records `RevokeSecurityGroupIngress`; EventBridge delivers it to `beacon-changes` typically within a minute or two, measured in H3; ledger row `pk=change, sk=<eventTime>#<eventID>`, with `actor_role` tagged `beacon remediation` when the principal is `BeaconRemediatorRole`).
2. App logs WARNING x2, then ERROR lines; metric filter -> `BeaconDemoInfra/ErrorCount`; alarm `beacon-demo-infra-errors` -> ALARM after the 60 s period (**preferred for the recorded take, with the on-screen clock**) or immediately via `make demo-alarm` (retakes only).
3. EventBridge -> `beacon-beacon`: `parse_event` -> ALARM trigger with the alarm's `state.timestamp`; `store.find_open_incident(alarm_name, 10 min)` dedup; `_fetch_all_logs` adds `[diagnostics]` and `[changes]` sources (`changes.recent()` filters to events **before** the alarm state-change time, ranks Revoke/Delete/Modify above Authorize/Create, and tags remediator-role events, so the `demo-reset` Authorize and SetAlarmState from seconds earlier are not named as the cause); budget/Cordon (reduction fires at `TOKEN_BUDGET=6000`, timeline entry `reduced (NN%)`); `triage()`; `rca.parse()`; deterministic override: if drift exists, `suggested_action=sg.restore_ingress` with exact params from `diagnose.py` regardless of model text.
4. `store.put_incident` writes `status=awaiting_engineer` (or `auto_remediating`), `rca_json`, `diagnostics`, `changes`, `timeline=[alarm_received, logs_fetched, reduced?, changes_found, rca_ready]`, `woken=true|false`, `ttl=now+30d`.
5. `contracts.match(alarm_name, suggested_action, params)` -> if a valid contract exists (`expires_at > now` in code, `uses < max_uses`, `params_hash` equal, params present in the golden snapshot) **and** `APPLY_ENABLED=true` on the triage function: `contracts.use()` (conditional `UpdateItem`: `uses < max_uses AND expires_at > :now`, atomic), `approvals.create(source=contract, transcript_quote=contract.transcript_quote)` (**`PutItem` on approvals, granted to `BeaconFunctionRole`**), `sfn.start_execution`, `notify(variant=contract)`; if a contract matches but `APPLY_ENABLED=false`: timeline `contract matched, apply disabled`, `notify(variant=page)`; else `notify(variant=page, link=DASHBOARD_URL?incident=<id>)`.
6. `prefetch.run` (existing) fills `cached_data` (metrics/logs/status) for `get_evidence`.
7. Browser polls `GET /incidents` every 3 s; new incident opens Talk; `POST /turn {mode: brief}` -> Strands agent calls `get_incident_brief` -> reply + Polly mp3 + speech marks.
8. Engineer asks; agent calls `get_evidence(kind)`; results become evidence cards E1..En (`kind='changes'` re-queries the ledger, so a late CloudTrail delivery still appears).
9. "Can you fix it?" -> `propose_fix()` -> the voice Lambda invokes `beacon-remediate` **synchronously (RequestResponse) with `{step:'dryrun', action, params, incident_id}`**; the DryRun therefore runs under `BeaconRemediatorRole` (the only role that can get `DryRunOperation` back; the voice role would always get `UnauthorizedOperation`); result `{ok, detail}` -> proposal `{fix_id:1, action, params, blast_radius, dry_run:{ok, detail, role:'BeaconRemediatorRole'}}` stored on the incident; agent reads back blast radius and asks for "approve fix 1". On a healthy stack (`make dry-run` in H3) `InvalidPermission.Duplicate` also counts as PASSED, since the permission check precedes the duplicate check.
10. "approve fix 1" -> `approve_fix(fix_id=1, confirmation_phrase)`; server checks the **current turn's raw transcript** (from `TurnContext`, never the model's argument) contains `approve fix 1` (number words normalised), passcode present, `APPLY_ENABLED=true`, proposal not expired (5 min), dry-run ok -> `approvals.create(channel=transcribe|webspeech|typed, transcript_quote=<verbatim transcript>)` -> `sfn.start_execution({approval_id, incident_id})` -> status `remediating`, `execution_arn`, `execute_requested_at` stored.
11. State machine: DryRun (fresh, remediator role) -> RequireApproval (fails without a record) -> Execute (idempotent; fails with reason `apply disabled` if `APPLY_ENABLED=false` on the remediate function; records `executed_at`) -> Wait 30 s -> Verify (all three: `describe_alarms` StateValue == OK **with `StateUpdatedTimestamp > executed_at`**; `get_metric_statistics(ErrorCount, Sum)` == 0 for the latest complete 60 s period; the action's `postcondition()`, for SG: the rule is present in `describe_security_groups`) -> loop up to 6 -> Resolved (`status=resolved`, `resolved_at`, SNS, `HumansWoken` metric) or Escalate (SNS, `status=escalated`). All three checks are written to the timeline as separate entries.
12. Browser sees `status=resolved` -> `POST /turn {mode:event, event:resolved}` -> Beacon speaks "Recovered. The alarm is back to OK. Should I handle this myself next time?" -> "Yes" -> agent **reads back the scope** ("Sleep Contract: restore tcp/5432 from sg-ecs on sg-rds when beacon-demo-infra-errors fires. Seven days, three uses. Say 'grant contract for seven days' to confirm.") -> "grant contract for seven days" (or "haan, saat din ke liye contract do") -> `grant_sleep_contract(days=7, max_uses=3)` verifies the explicit phrase against the transcript and that a read-back is pending -> contract row with `params`, `params_hash`, `expires_at`, TTL and quote.
13. `make demo-sleep` (re-break + alarm) -> step 3-5 with a contract match -> Step Functions -> Resolved -> SNS "Resolved under Sleep Contract; you were not woken" -> moon badge on the Night Board.

### 4.5 Remediation and safety model

- **Allowlist by code:** `src/beacon/remediation/registry.py` maps exactly two ids to `ActionSpec(id, description, params_schema, iam_actions, blast_radius(params), dry_run(params), execute(params), postcondition(params), verify(incident), confirmation_phrase(fix_id))`. Anything else is unexecutable.
  - `sg.restore_ingress` (`actions_sg.py`): params `{group_id, ip_protocol, from_port, to_port, source_group_id}`; precondition: the rule must exist in the golden snapshot (SSM `/beacon/<stack>/golden-sg`, JSON `{group_id: [IpPermissions...]}` written by `make snapshot-sg` on a healthy stack); dry-run: `authorize_security_group_ingress(DryRun=True)` expecting `DryRunOperation` (would succeed) or `InvalidPermission.Duplicate` (permission check passed, rule already present) vs `UnauthorizedOperation`; execute: same call, `InvalidPermission.Duplicate` treated as success; postcondition: the rule is present in `describe_security_groups`; verify: see below.
  - `ecs.force_redeploy` (`actions_ecs.py`): params `{cluster, service}`; precondition: `describe_services` ACTIVE; execute: `update_service(forceNewDeployment=True)`; postcondition: a new deployment id in `describe_services`; verify: see below. Kept in the allowlist to prove it generalises; not demoed.
- **Allowlist by data:** the golden snapshot means the SG action can only restore rules the operator blessed.
- **Dry-run before every execute, always under the remediator role:** `propose_fix` invokes `beacon-remediate` with `{step:'dryrun'}` (RequestResponse, 10 s client timeout) and the state machine dry-runs again (fresh) before Execute. The voice role never calls EC2/ECS; it has `lambda:InvokeFunction` on the remediate function ARN only.
- **Approval is a record, not a prompt:** `RequireApproval` state reads `beacon-approvals-<stack>` and fails without a valid record; approvals carry `{approval_id, incident_id, action, params, params_hash, source: voice|typed|cli|contract, transcript_quote, granted_at, expires_at, ttl(30 d)}`.
- **Transcript-verified consent:** `approve_fix` and `grant_sleep_contract` decide on the raw user transcript of the current turn (`TurnContext.transcript`), never on the model's tool arguments; the model cannot approve itself. Exact phrase `approve fix <n>` for a one-shot fix. **The stronger permission gets the stronger gate:** a contract needs (a) a read-back turn in which the agent states alarm, action, exact resources, days and uses and sets `contract_readback_pending` on the incident row, then (b) the explicit phrase `grant contract for <n> days` or the Hinglish equivalent (`saat din ke liye contract do`) in the next turn's transcript. Loose affirmatives (`yes`, `haan`, `do it`, `theek hai`) only trigger the read-back; they never grant.
- **Executes once:** Powertools `@idempotent_function` keyed on `approval_id` (`beacon-idempotency-<stack>`); `make replay-approval APPROVAL=<id>` demonstrates the cached result in the log.
- **Least privilege:** `BeaconRemediatorRole` policy has **two statements for the SG action** because `ec2:AuthorizeSecurityGroupIngress` is authorised against both the `security-group` and the (not-yet-tagged) `security-group-rule` resource: (1) `ec2:AuthorizeSecurityGroupIngress` on `arn:aws:ec2:${Region}:${Account}:security-group/*` with `Condition: StringEquals: aws:ResourceTag/beacon:remediable: "true"`; (2) `ec2:AuthorizeSecurityGroupIngress` on `arn:aws:ec2:${Region}:${Account}:security-group-rule/*` with no tag condition (only `ec2:Region`). Plus `ecs:UpdateService` with the tag condition on the service ARN, `ec2:DescribeSecurityGroups`, `ecs:DescribeServices`, `cloudwatch:DescribeAlarms`, `cloudwatch:GetMetricStatistics`, `ssm:GetParameter` on `/beacon/*`, DynamoDB on approvals/incidents/contracts/idempotency, `sns:Publish`, `xray:PutTraceSegments`/`PutTelemetryRecords`. `BeaconVoiceTurnRole` has zero EC2/ECS write actions (a unit test parses the templates to prove it, and also asserts the two SG statements, the positive grants on `BeaconFunctionRole`, and X-Ray on every role whose function has `TracingConfig Active`). `BeaconDashboardRole` is read-only. `BeaconMicRole` is Transcribe-only. `make dry-run` (invokes `beacon-remediate {step:'dryrun'}` with the demo SG params) is run **Friday night in H3**, so an IAM surprise is found with 9 hours of agent time left, not on Saturday morning.
- **Verified, or a human is paged:** Verify is not a boolean read of a possibly-forced alarm. It requires all three: alarm `StateValue == OK` with `StateUpdatedTimestamp` later than the Execute step's `executed_at` (so a `set-alarm-state` flip or a pre-existing OK cannot satisfy it); `ErrorCount` Sum == 0 for the latest complete period via `get_metric_statistics`; the action's `postcondition()` (SG rule present). Loop 6 x 30 s; Escalate publishes to SNS and marks the incident `escalated`. The timeline shows all three checks as separate rows with timestamps. For the recorded take, the alarm is left to fire on real data (2-3 min, on-screen clock); `make demo-alarm` is for retakes only.
- **Contracts are resource-scoped and expire on their own:** a contract stores `alarm_name`, `action`, `params` (exact `group_id`/`source_group_id`/ports, or `cluster`/`service`), `params_hash`, `expires_at`, `max_uses`, `uses`, `transcript_quote`, `granted_by`; `contracts.match` requires alarm, action and `params_hash` equality **and** golden-snapshot membership of the params; `expires_at > now` is checked in code (DynamoDB TTL deletion can lag up to 48 h); `contracts.use` is a conditional `UpdateItem` (`uses < :max AND expires_at > :now`) so two triage runs cannot both consume the last use. The Contracts card shows the scope (resource ids), uses left and expiry; revoke button.
- **Public URL protection:** passcode header on `/session` and `/turn` (passcode is a `NoEcho` CloudFormation parameter of the console stack, persisted in the gitignored `.beacon.env` so redeploys keep it), `APPLY_ENABLED` kill switch, per-incident turn cap, CloudWatch billing alarm at $20 (human sets it once), dashboard redaction of account id and actor ARN.
- **Kill switch that actually stops writes:** `APPLY_ENABLED` is a parameter on all three templates and is read in **three** places: `approve_fix`/`grant_sleep_contract` (voice), the contract-match branch (triage), and the Execute step (remediate, which fails the execution with reason `apply disabled`). `make apply-off` / `make apply-on` update the env of all three functions (`update-function-configuration` with the existing env merged, since that call replaces the whole map) **and** write `APPLY_ENABLED` into `.beacon.env` so the next deploy does not silently re-enable it. `/safety` shows the switch state per function.

## 5. Live UI spec

**Stack:** Vite 8 + React 19 + TypeScript, no component library, hand-written tokens in `web/src/theme.css`, Inter (UI) + JetBrains Mono (evidence) from Google Fonts, one custom `Sparkline` SVG component, `vite-plugin-node-polyfills` for the Transcribe SDK. Config from `/config.json` at runtime (`{voiceUrl, dashboardUrl, region, sttLanguage, voiceBackend, archivedIncidentId}`; served with CachingDisabled so the URLs never require a rebuild or wait on a 24 h TTL). Passcode entered once, kept in `sessionStorage`.

**Visual direction (Best UI):** "night shift". Background `#0B1020`, surface `#121A33`, text `#E6E9F2`, dim `#8B93A7`, amber `#FFB020` (alarm / awaiting your word), green `#2ED47A` (verified), red `#FF5C5C` (escalated), moon lilac `#B8A6FF` (handled while you slept). Motion restrained: chips pulse, cards slide in, sparkline draws. Phone width first: single column, 16 px gutters, no horizontal scroll; desktop: two columns (Night Board left, Talk right). `prefers-reduced-motion` respected. Dark only (light theme cut).

**Real-time mechanism:** polling, no WebSockets. `useIncidents` hits `GET /incidents` every 3 s; `useIncident(id)` hits `GET /incidents/{id}` every 2 s while status is not terminal (the change card is re-read from the ledger on each poll, so a late CloudTrail delivery fills it in) and `GET /incidents/{id}/execution` every 3 s while `remediating`; contracts every 10 s. The Talk screen reacts to status transitions (`awaiting_engineer` -> auto-brief once; `resolved` -> event turn; `escalated` -> event turn).

### Screens and states

1. **Night Board** (`/`): Tally strip (incidents handled, median minutes to recovery, humans woken) from `GET /tally`; incident feed, newest first; each card: severity pill from `rca_json.status`, alarm name, age, status pill (`awaiting_engineer` amber / `remediating` amber pulsing / `resolved` green / `escalated` red / `auto_remediating` lilac), moon badge when `handled_by == contract`. Expanding a card shows the vertical timeline from `timeline[]` with hard timestamps: alarm received, logs fetched (n lines), reduced (NN%), change found (CloudTrail card: eventName, actor shown as `user/<name>` with the account id masked, time, user agent; remediator-role events labelled "beacon remediation"), RCA ready, fix proposed (blast radius + dry-run result + "dry-run via remediator role"), approved (source + quoted transcript), executing (Step Functions state names ticking from execution history), verified (three rows: alarm OK after execute, ErrorCount 0, rule present; sparkline of ErrorCount to zero), resolved / escalated, contract granted / used. **Empty state:** "All quiet. Waiting for the next page." with the passcode field **and an "Archived run" card** (from `config.archivedIncidentId`, or the bundled `/replay/incident-001.json` if the table is empty) with a visible **Replay this run** button that opens the replay view, so a judge weeks later sees the product without knowing a query string.
2. **Talk** (`/talk/:incidentId`): full-width push-to-talk button with live waveform; streaming partial transcript; Beacon's reply as a speech bubble whose sentences highlight as Polly reaches them (speech marks) and whose `[E#]` chips pulse; a sentence with no citation while evidence exists gets a dim "unverified" badge; tool chips under the bubble (`get_evidence`, `propose_fix`, `approve_fix`...) with args summary on hover; Evidence Dock: numbered cards E1..En (log excerpt, metric datapoints with sparkline, change event, SG drift diff, dry-run output); Fix Card flips amber "awaiting your word: say 'approve fix 1'" -> green "executing" -> "verified (3/3 checks)"; Contract read-back card ("say 'grant contract for seven days'"); typed input under the mic; STT selector (Transcribe / Web Speech / typed) and a latency strip (STT ms / agent ms / TTS ms measured client-side). States: idle, listening, thinking, speaking, awaiting-approval, awaiting-contract-phrase, executing, resolved, escalated, error (with retry).
3. **Contracts** (`/contracts`): cards with alarm name, action, **scope (exact resource ids from `params`)**, uses left, expiry countdown, the sentence that granted it (quoted), granted_by channel, Revoke button (passcode). Empty state explains what a Sleep Contract is.
4. **Safety** (`/safety`): allowlist rendered from `GET /safety` (registry ids, params schema, blast radius text, IAM actions), the remediator IAM statements with the tag condition and the `security-group-rule` statement, the approval ledger (last 20 approvals with quotes), the kill-switch status (`APPLY_ENABLED` **per function: triage, voice, remediate**).
5. **Replay** (`?replay=1` or the Archived-run button): loads `public/replay/incident-001.json` captured from a real run; Night Board + Talk render from it; Talk answers from recorded turns; no AWS calls. Banner "REPLAY of incident from <real date and time>".

### "What we learned" seed bullets (Learning criterion)
- Nova 2 Lite tool use through Strands: what worked at temperature 0.3, where the model over-called tools, and why we cap turns.
- `cloudtrail:LookupEvents` lags minutes; the EventBridge `AWS API Call via CloudTrail` path needs a trail and arrived in <measured> seconds in our runs, but is not guaranteed, so the UI polls for it.
- EC2 `DryRun=True` returning `DryRunOperation` is the cheapest safety primitive on AWS, and it only tells the truth when the caller is the role that will execute.
- `aws:ResourceTag` conditions turn "the agent can change security groups" into "the agent can change these two resources", but `AuthorizeSecurityGroupIngress` also authorises against the untagged `security-group-rule`, so the policy needs two statements.
- Powertools idempotency keyed on an approval id is a one-decorator answer to "what if the loop retries".
- Lambda container images with `:latest` do not redeploy; git-SHA tags with a deploy guard do. ARM64 task definitions and x86 laptops do not mix. Copy source last so rebuilds push kilobytes, not gigabytes.
- Transcribe streaming from the browser works with 15-minute STS credentials scoped to one action; no identity pool needed (and Vite needs Node polyfills for the SDK's event stream).
- Polly sentence speech marks make a voice UI legible with the sound off.
- Step Functions execution history is a free product timeline.
- Verification is a loop, not a boolean: alarms take one or two evaluation periods to clear, and "OK" only counts if it happened after the fix.
- A standing approval deserves a stronger gate than a one-shot approval: read back the scope, then require the phrase.

## 10. AssemblyAI phase plan (Sept 21-30)

**Abstraction boundary in code:**
- Browser: `web/src/voice/transport.ts` interface `VoiceTransport { start(session), stop(), onPartial, onFinal, onAgentText, onAgentAudio, onToolCall, onInterrupted, onTurn, sendToolResult }`; implementations `TranscribePollyTransport` (First Commit cascade), `AssemblyAIAgentTransport` (Voice Agent WebSocket), `AssemblyAIRealtimeSttTransport`. - Everything else (triage, ledger, registry, Step Functions, contracts, dashboard, DynamoDB, Bedrock inside tools) is unchanged; Bedrock still reasons over evidence inside `get_evidence` and the RCA, so the AWS stack stays live and both entries share one backend.
